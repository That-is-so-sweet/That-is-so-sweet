# 揪甘心 — 系統流程圖

本頁補充 [SPEC.md](./SPEC.md)、[PRD](./prd/README.md) 的文字規格，用兩張圖呈現 Phase 1 的完整系統流程：第一張是「主揪建立活動 → 參與者投票 → 主揪定案／取消／重新開放 → 留言」的完整流程與驗證關卡；第二張是活動狀態（進行中／已定案／已取消／連結失效）之間的轉換關係。圖中節點標註的 FR 編號對應 [SPEC.md 第 4 節](./SPEC.md)的功能需求。

---

## 一、主流程圖

```mermaid
flowchart TD
    subgraph SG1["建立活動"]
        n1(["主揪開始建立活動"]) --> n2["填寫活動名稱、主揪姓名、<br/>候選時段模式與候選時段、回覆截止時間、<br/>主揪 Email（選填）、地點／說明（選填）"]
        n2 --> n3{"欄位驗證通過？<br/>（FR-1，見 SPEC 第4.2節）"}
        n3 -- "是" --> n4["系統建立活動並產生分享連結（FR-1／FR-2）"]
        n4 --> n5{"有填主揪 Email？"}
        n5 -- "是" --> n6["寄送含分享連結的通知信"]
        n5 -- "否" --> n7["分享連結給參與者"]
        n6 --> n7
        n3 -. "否" .-> n2
    end

    subgraph SG2["開啟連結與狀態判斷"]
        n8(["任何人開啟活動連結"]) --> n9{"連結已失效？<br/>（已定案且超過7天，FR-9）"}
        n9 -- "是" --> n10["顯示連結已失效畫面"]
        n9 -- "否" --> n11{"活動目前狀態"}
        n11 -- "已取消" --> n12["顯示已取消畫面<br/>（留言仍可瀏覽）"]
        n11 -- "已定案" --> n13["顯示定案結果畫面<br/>（出席名單／日曆匯出）"]
        n11 -- "進行中" --> n14["進入投票畫面"]
    end

    subgraph SG3["投票"]
        n15["輸入暱稱、Email（選填）、密碼（選填）"] --> n16{"暱稱已存在且設有密碼？"}
        n16 -- "未設密碼或密碼相符" --> n18{"投票已截止？"}
        n18 -- "否" --> n20["針對每個候選時段<br/>明確選擇可行／可能可以／不可行（FR-3）"]
        n20 --> n21{"所有時段皆已選擇？"}
        n21 -- "是" --> n22["送出投票，系統更新彙整統計（FR-4）"]
        n16 -- "密碼不符" --> n17["阻擋：密碼不正確"]
        n18 -- "是" --> n19["阻擋：投票已截止，請聯繫主揪重新開放"]
        n17 -.-> n15
        n21 -. "否，不提供預設值" .-> n20
    end

    subgraph SG4["主揪彙整與操作"]
        n23["主揪查看彙整／熱點圖"] --> n24{"主揪身分驗證<br/>（姓名＋Email 完全比對，第5.4節）"}
        n24 -- "相符" --> n26{"主揪選擇動作"}
        n26 -- "定案" --> n27{"所選時段存在於候選清單？"}
        n27 -- "是" --> n29["狀態→已定案（FR-5）<br/>計算出席名單（僅計可行者，FR-6）"]
        n29 --> n30["寄送定案通知給所有留 Email 的參與者（FR-6）"]
        n26 -- "取消" --> n31{"已經是已取消？"}
        n31 -- "否" --> n33["狀態→已取消（FR-7）<br/>立即阻擋新投票／新留言<br/>通知已回覆的參與者"]
        n26 -- "重新開放（僅限已定案）" --> n34["狀態→進行中（FR-7）<br/>清除最終時段<br/>確保截止時間在未來"]
        n24 -- "不符" --> n25["拒絕操作：身分驗證失敗"]
        n27 -- "否" --> n28["阻擋：所選時段無效"]
        n31 -- "是" --> n32["阻擋：已經取消過了"]
    end

    subgraph SG5["留言"]
        n35["留言：輸入暱稱＋內容（FR-8）"] --> n36{"活動已取消或連結已失效？"}
        n36 -- "否" --> n38["留言送出並顯示於留言列表"]
        n36 -- "是" --> n37["阻擋留言"]
    end

    n7 --> n8
    n14 --> n15
    n22 --> n23
    n13 --> n23
    n14 --> n35
    n13 --> n35
    n12 --> n35

    n30 -.-> n13
    n33 -.-> n12
    n34 -.-> n14
```

> 圖中實線箭頭為正向流程；虛線箭頭代表「重試」或「主揪操作後回到某畫面」的迴圈，非主要閱讀路徑。

## 二、活動狀態轉換圖

```mermaid
stateDiagram-v2
    direction LR
    [*] --> 進行中 : 建立活動（FR-1）
    進行中 --> 已定案 : 主揪定案（FR-5）
    已定案 --> 連結失效 : 最終時段日期起算超過7天（FR-9）
    連結失效 --> [*] : 終止狀態
    進行中 --> 已取消 : 主揪取消（FR-7）
    已定案 --> 已取消 : 主揪取消（FR-7）
    已取消 --> [*] : 終止狀態，不可逆
    已定案 --> 進行中 : 主揪重新開放，清除最終時段（FR-7）
```

**補充說明**：

- 「已取消」與「連結失效」都是終止狀態，但阻擋範圍不同——已取消會立即阻擋新投票與新留言（見 FR-7），連結失效則會阻擋所有互動（投票、留言、查看彙整，見 FR-9）。兩者判斷邏輯彼此獨立：連結失效只針對「已定案且已選定最終時段」的活動計算天數，「進行中」的活動不論多舊都不會因此失效。
- 「重新開放」只能從「已定案」回到「進行中」，「已取消」目前沒有任何路徑可以回到其他狀態。
